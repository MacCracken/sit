# 2026-11-06 — security pass for 1.13.2

**Scope**: the release's changes, and five findings owl's P(-1) audit (2026-10-31, owl 1.5.3) filed against sit 1.13.0's read bundle. Severity as [CLAUDE.md](../../CLAUDE.md) defines it.

## Findings closed

| id | severity | finding | fix |
|---|---|---|---|
| owl INFO-004 | HIGH | `sit_diff_path` flattened all of HEAD to find one path. A 200 KB `.git` cost a viewer 1.7 GB, or out of memory | `tree_path_find`, one tree per component; `flatten_tree` bounded at 256 MiB, inside a tree too |
| owl INFO-005 | MEDIUM | The read API waited without limit on `.sit/objects.flock`, which any reader of a shared repository can lock, and a view created the file | `sit_set_store_wait`, 60 s by default, `SIT_BUSY`; `_store_lock_create` |
| owl INFO-006 | MEDIUM | Unreadable read as absent, too big to diff as unchanged | `sit_last_result`; `obj_fail_note` records why a read failed |
| owl INFO-007 | LOW | `.gitattributes` not applied in read mode | `src/git_attr.cyr` |
| owl INFO-008 | LOW | `commit_tree_hex` dangled in the read bundle | moved to `commit.cyr`; integration section 49 |

## Found during the pass

| severity | finding | fix |
|---|---|---|
| MEDIUM | `sit_diff_path` read through a tracked symlink: `read_file_fl` follows the last component, so a retargeted link put the file it names into the caller's diff | the worktree side of a link is its target (`_api_work_side`) |
| MEDIUM | `sit_diff_path` read a file behind a closed directory as deleted: `lstat`'s -1 means "not there" and "cannot look" alike | `path_is_absent` ([architecture 007](../architecture/007-exists-means-readable.md)) |
| LOW | `sit blame` wrote an author's bytes raw; only reachable from a `.git/` author, so new with this release's opening | `write_sanitized` |
| LOW | A status poll on a hostile tree kept 256 MiB per call on the bump heap, even once bounded | the refused commit is remembered per repository (`_api_big_head`, reset in `sit_repo_open`) |

## Reviewed, no finding

- **New parser, `src/git_attr.cyr`.** A line is at most 2,047 bytes, so `_ga_line`'s 2,048-byte unquote buffer holds it. `gitattr_lookup` refuses a path of 4,096 bytes or more before its 4,128-byte buffer. Macros are capped at 64 and each expands at most once per lookup, which also ends a cycle. Attribute files are read only when regular by `lstat`, and under 1 MiB. Fuzzed, and clean under the poisoned allocators with A/B identical output.
- **No command runs.** `filter` is never executed; there is no `exec` or `sys_system` in the new code. The only `syscall` is `newfstatat` in `path_is_absent`, on the path `path_lstat_mode` already stats.
- **`.git/packed-refs` tag names** are bytes from the repository: they are printed through `write_sanitized` and never used as paths.
- **`_pack_link_result`** inflates into a 32-byte stack buffer, bounded by sankoch's `dst_cap`, and parses it within those 32 bytes.

## Left open

- A `.git/` repository's file over 16 MiB of unchanged size reads as not compared. Status needs git's stat data for that (1.14.0's DIRC reader).
- `_read_whole` opens by path after its checks, so a worktree swapped between `lstat` and `open` is followed once. The caller is a read-only view, and the same race exists in every reader of a worktree. Unchanged.
- A store with pre-patra loose objects migrates them on first open, a read API call included ([architecture 008](../architecture/008-gc-runs-alone.md)).
