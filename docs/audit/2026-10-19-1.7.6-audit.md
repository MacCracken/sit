# Security + correctness audit — 2026-10-19 (v1.7.6, closes 1.7.x)

The P(-1) hardening and closeout pass for the last 1.7.x patch. **Scope:** everything that changed since the 1.6.4 audit ([`2026-10-19-audit.md`](2026-10-19-audit.md)): 1.7.0 → 1.7.5: 2,142 lines added and 659 removed across 18 `src/` files, including bearer tokens bound to remotes, the patra 1.16 write-status sweep, `sit serve`'s request arena and ref pushes, git read mode's iterative delta resolver and mapped packs, and the 1.7.5 stack-buffer rewrite of the ref-write helpers. The code those releases touched was re-read in full, not only the diffs.

**Method.** Four independent reviews, each reproducing its findings against the 1.7.5 build in scratch repos and listing what it checked and found clean:
- **N — network:** `serve.cyr`, `wire*.cyr`, the sandhi server loop sit relies on
- **L — local writes:** every command that rewrites the worktree, the index, refs or repo state
- **R — the untrusted read path:** git read mode, the public API owl and thoth run in-process, pack / idx / delta parsing
- **X — external research:** VCS advisories from January 2025 to October 2026 (git, go-git, gitoxide, libgit2, dulwich, isomorphic-git, jj, Git LFS, forges), checked against sit

Two more came from re-reading the fixes themselves (**K**). Every finding was re-run before and after its fix with the reviewer's script, and each fix has a regression test that fails on 1.7.5 (below).

**Headline: the client stored whatever a server sent.** `fetch` and `clone` copied objects into the store under the id the server named without hashing them, so a hostile server (or a proxy in front of an honest one) could swap a blob under a signed commit and `verify-commit` still said "good". Below that, the pattern of 2026-10-19 held: the worst local defects were data loss with exit 0 in ordinary commands — an octopus merge over an uncommitted edit, `reset --hard` turning the next commit into a merge, a stash discarding a file, a rebase dropping a commit's change, a checkout deleting a directory whose tree object was missing.

## HIGH — all fixed

| # | Defect | Repro on 1.7.5 |
|---|---|---|
| N1 / X2 | fetch / clone stored objects without checking that they hash to their id | a proxy answering one blob id with other bytes: clone rc 0, the substituted file checked out, `verify-commit` "good" |
| L1 | octopus merge overwrote uncommitted edits (an A1 regression) | `echo WORK > a.txt; sit merge b1 b2` → rc 0, a.txt reset |
| L2 | `reset --hard` kept MERGE_HEAD; the next commit, on any branch, recorded the abandoned merge | conflicted merge, `reset --hard HEAD`, commit → 2 parents |
| R1 | `sit_repo_status` / `sit_diff_path` kept every blob and worktree file they compared | 200 files × 50 KB: 10 MB kept per status call, 202 MB resident growth over 10 calls in the consumer |

**N1.** ADR 0006 and CLAUDE.md said not to re-hash on the transfer path, for speed, and left verification to `fsck`. That made the transport the trust boundary. The fix ([ADR 0006, amended](../adr/0006-batched-want-frame-format.md#amendment--176-the-client-verifies-what-it-stores)): every object sit stores from elsewhere is inflated, its framing type checked against the type it was sent as, and its SHA-256 compared with its id **before** it lands and before any ref moves. Commits and trees are verified where the walk reads them (it inflates them anyway); blobs in `copy_objects`. `sit serve` checks pushed objects the same way (`_object_verify`, shared). Still no recompression: the compressed bytes stored are the bytes received. Cost, by CPU time against 1.7.5: a 100-commit file:// clone goes 77.4 → 87.6 ms, of which verification is 6.6 ms (81.0 ms with it short-circuited); on blob-heavy content it is one SHA-256 pass over the received bytes — 500 compressible 21 KB blobs clone in 0.63 s CPU against 0.44 s.

**L1.** `cmd_merge_octopus` never called `is_dirty()` and then told the materializer the check was done. It refuses a dirty tree now, as the two-way merge does.

**L2.** `reset --hard` clears MERGE_HEAD, CHERRY_PICK_HEAD and REVERT_HEAD, as git does, and `checkout` (without `-b`) refuses while any of them exists.

**R1.** Both buffers are freed after the compare (`read_file_fl`, a freelist twin of `read_file_heap`); `.sit`-mode reads return freelist buffers since R10, so the API can free what either backend returns. `packed-refs` and a detached `.git/HEAD` are read into freelist buffers freed after the lookup, and `tree_find_release` drops the per-call `tree_find` map the API built. Measured with a probe built from `dist/sit-read.cyr` (integration section 34):

| 200 files × 50 KB, git repo, 10 calls | 1.7.5 | 1.7.6 |
|---|---:|---:|
| `sit_repo_status`, bump heap kept per call | 10,095,656 B | 93,968 B |
| `sit_repo_status`, resident growth | 202,384 KB | 80 KB |
| `sit_diff_path` (unchanged file), kept per call | 110,739 B | 59,752 B |

The ~94 KB left per status call is the flattened HEAD tree, the worktree listing and the result records, all on the bump heap. Running each API call on an arena it rewinds, as `sit serve` does per request, would close it; that is the roadmap's API-arena item.

## MEDIUM

| # | Defect | Status |
|---|---|---|
| N2 | pushes of objects over ~64 KiB failed over every network transport | **Fixed.** `sit serve` sizes its request buffer at 16 MiB + 64 KiB on all three loops (plain, `--tls`, `--stdio`) through `sandhi_server_options_max_request`; a 200 KB object pushes over each |
| N3 | the TOFU pin store was rewritten in place, and a failed write ignored | **Fixed.** Lock file, re-read under the lock, atomic rename; an existing pin file that cannot be read refuses the connection instead of reading as "no pins" (existence by `lstat`: `file_exists` opens the file, so the first cut of this fix still called an unreadable file absent — caught by its integration test) |
| N4 | `sit serve`'s fast-forward check had no work bound | **Fixed.** The walk carries a deadline (60 s, the TLS request deadline) and answers 503 when it passes |
| L3 | a conflicted merge wrote over an untracked file at a conflict path | **Fixed.** Refused before anything is written; the conflict record is written before the worktree too |
| L4 | `sit rm` deleted a file with unstaged edits, unrecoverably | **Fixed.** Refused unless `--cached` |
| L5 | ref writes were not atomic, and a ref that was not a commit id read as "unborn" | **Fixed.** Every ref and state file goes through `sf_write_atomic` (`<path>.lock`, `O_EXCL`, fsync, rename); `commit` / `pull` refuse a branch whose ref is broken (`head_ref_broken`) instead of starting a new root over it |
| L6 | `stash` discarded a file HEAD tracks but the index does not (after `rm --cached`) | **Fixed.** Refused while such a file differs from HEAD |
| L7 | `rebase --continue` after a non-conflict stop committed the step as an empty commit | **Fixed.** A stop that left no CHERRY_PICK_HEAD / CONFLICTS re-applies the step; a resolution equal to HEAD's tree is skipped, not committed empty |
| L8 | a missing subtree was read as an empty directory below the root | **Fixed.** `flatten_tree` propagates a subtree's failure; HEAD's tree is read through `commit_tree_entries`; merge, cherry-pick, revert, octopus and `diff <a> <b>` refuse an unreadable tree instead of treating it as empty. 1.7.5 deleted the directory, rewrote the index and reported "clean" |
| L9 | a clean 3-way merge could move an insert across a repeated line | **Fixed.** An insert-only hunk now conflicts with any hunk whose base range touches it, at either end (1.6.4 covered only the start). Differential against `git merge-file`, 400 random cases: 78 clean merges identical, 0 differing; the 32 cases sit merges and git conflicts on are all edits to *adjacent, distinct* base lines, which sit applies both of (git's adjacency rule is more conservative) |
| L10 | re-running `sit init` moved HEAD to main | **Fixed.** HEAD is written only by a fresh init |
| L11 / X1 / X3 | file:// push: branch name unvalidated; wrote outside the remote and through a symlinked ref | **Fixed.** `refname_valid` on the branch; the remote ref is written root-anchored and atomically (`sf_write_atomic_at`); a symlinked remote ref is refused, not read as "no tip" |
| L12 | an index write patra failed to land was reported as success | **Fixed in sit**; the patra side is already on patra's roadmap. `index_upsert` and the new `index_rename_path` (for `sit mv`) each run in one transaction, which patra reports honestly; `index_remove_path`, left without callers, is removed; in autocommit a failed page write inside `tbl_insert` / `btree_insert` was not (patra) |
| R3 | an empty object in a pack could not be read | **Fixed.** A 0-byte inflate is valid; the result must equal the declared size, as git requires |
| R4 | crafted delta chains cost minutes of CPU per read | **Fixed.** A 4 GiB budget on what one read may produce across its chain (`--depth=250` at the 16 MiB object ceiling); delta copies go eight bytes at a time; the last pack that answered is asked first, so a REF chain does not re-list the pack directory per link. A 4095 × 16 MB chain (a 114 KB pack): 244 s of CPU → refused in 1.1 s; a 40 × 16 MB chain still reads, byte-identical and 5.4× faster (0.46 s CPU vs 2.48 s); a REF cycle beside 1,000 packs: 12.9 s → 0.04 s. The first cut's 1 GiB refused real repacks (V1, below) |
| R5 | a REF_DELTA with a loose base kept that base on every read | **Fixed.** The loose reader's buffer is freed when the chain is done |
| R7 | reading a reflog took quadratic time | **Fixed.** One pass. 5,000 entries: `fsck` / `reflog` 10.8 s → 0.02 s CPU; 20,000 now 0.06 s |
| R8 | a refused Myers diff kept ~73 MB of trace | **Fixed.** The trace slices are freed on the refusal path |
| R9 | `sit_diff_path` diffed an unchanged file, against its contract | **Fixed.** Returns 0 for equal buffers, and frees them; also frees them when the diff table's cap refuses |
| R10 | in a .sit repo every blob compressing past 4:1 took a fresh 16 MiB buffer per read | **Fixed.** One inflate, `obj_inflate_fl`, replaces seven copies of the sizing and sizes the retry from the object's own header; freelist memory. 500 compressible blobs: `fsck` peak 2,137 MB → 30 MB, `clone` 1,071 MB → 18 MB (transparent huge pages on) |
| R2 | git-mode status is wrong on ordinary repos: 100755 / 120000 / 160000 entries and names failing sit's checkout rules are dropped; alternates are not read | **Deferred** (roadmap 1.11.0, with `.git/` CLI parity). It needs mode-aware tree entries through the read path, which is new surface for the API |
| R6 | a second repo opened in one process reuses the first's object store handle and pack mappings | **Deferred** (roadmap 1.10.0, serving many repos). 1.7.6 resets the new last-pack cache per `sit_repo_open`, so it adds no exposure; the patra handle and the mapping cache are still per process |

## Closeout review of the fixes (V)

An independent review of the finished 1.7.6 diff (CLAUDE.md closeout step 5) read every hunk and re-ran its repros against both builds. It found five regressions in the first cut of the fixes above — none in 1.7.5, so they are not in the totals — and confirmed the rest clean: no use-after-free from the new frees, no legitimate sit or git commit refused by the header-order rule, inflate sizing sound for a header that lies, the banned Cyrius constructs absent. All five are fixed and tested:

| # | Regression | Fix |
|---|---|---|
| V1 | R4's 1 GiB chain budget refused objects git and 1.7.5 read: a 12 MB file with 160 revisions, `git repack --depth=250` (chains to 157), lost 76 of 161 revisions | the budget is 4 GiB, `--depth=250` at the 16 MiB object ceiling; all 161 read byte-identical to git; `deep_pack.py` reads a 100 × 16 MB chain |
| V2 | L7's `rebase --continue` re-applied a step whose tree had landed but whose ref write failed, and then refused the "dirty" tree on every `--continue` | re-apply only when the index is still at HEAD's tree; otherwise commit it (L7b test) |
| V3 | `sf_write_atomic` replaced a 0600 `~/.sitconfig` with a 0644 file | the lock file takes the replaced file's permission bits before the rename |
| V4 | `sit show` still ignored `flatten_tree`'s result, which now stops at the first bad subtree: every later file would print as deleted | refuses, as `diff` does |
| V5 | X5's ownership test followed a symlink at `.sit/config` | `lstat` on `.sit/config`, and `.sit/` itself must be the user's (git's safe.directory test) |

## Upstream asks

## External research (P(-1) step 4)

The advisories were read for classes rather than exact bugs. Besides X1–X5 above, these were checked and found not to apply: path traversal through tree entries and NTFS / HFS+ aliases (sit's tree-name rules, since 1.3.x); symlink-then-file checkout races (no symlink entries; `_sf_parent_symlink` on every write); submodule / `.gitmodules` command injection (no submodules); credential-helper and `core.*` command execution from repo config (sit executes nothing from config); `--upload-pack`-style argument injection over ssh (leading `-` refused, `--` sentinel); packfile index geometry and delta bounds (S-24, fuzzed); ref names with control bytes or `..` (refname_valid); and terminal escapes in names (E8 / E10, extended here by L16 / R13).

## Verification

- **Unit:** 543 → 566 (`test_176_pure`: header order, frame sizing, `obj_inflate_fl` on a 1000:1 object, the refs parser bound, reflog line starts, `_pack_copy`, option-shaped names, `alloc_or_die(0)`; the L9 overlap cases replace the 1.6.4 assertion that called an end-touching insert disjoint).

- **Fuzz:** 18 → 20 targets (`fuzz_obj_inflate`, `fuzz_http_refs`), no crashes.
- **Poison A/B:** the full integration suite run against two poisoned builds (freed memory quarantined and filled with two different patterns, every allocation redzoned — an overwrite exits 86). No redzone fired and every assertion passes under both except section 27's two RSS-growth bounds, which measure memory reuse that quarantine disables by design.
- **Other targets and downstream:** the aarch64 build passes `deep_pack.py` under qemu (16/16, the word-wise delta copy included), and `--agnos` builds; owl (cyrius 6.6.2, 7/7 tests) and thoth (6.6.6) build against the new `dist/sit-read.cyr`.
- `cyrius lint` clean across `src/`.

## Result

Every HIGH and every LOW is fixed; two MEDIUMs are deferred to the minors whose surface they need (R2 → 1.11.0, R6 → 1.10.0). The CLAUDE.md rule on wire transfer is revised to the new trust model: verify everything stored from elsewhere, still never recompress.
