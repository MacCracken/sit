# Security + correctness audit — 2026-10-20 (v1.12.2, closes 1.8.0 → 1.12.1)

The P(-1) hardening and closeout pass that ends the 1.12.x arc, before 1.13.0.

**Scope.** Everything that changed since the 1.7.6 audit ([`2026-10-19-1.7.6-audit.md`](2026-10-19-1.7.6-audit.md)), 1.8.0 → 1.12.1: 4,672 lines added and 500 removed across 22 `src/` files. That is five minors without a closeout, and the most new surface since 1.0:
- packs and `sit gc` (a new on-disk format, a store swap, the store lock; ADR 0016, architecture 008);
- `sit serve --repos`, base-path URLs and store sessions (ADR 0017);
- `.git/` CLI parity, alternates and relaxed tree reading (ADR 0011's 1.12.0 amendment);
- 1.8.0's `merge -m`, three-way `stash pop`, reflog expiry and `@{<time>}`, and `fsck --prune` dating;
- 1.9.0's cmdit dispatch and completions, and 1.12.1's `sit add` of several paths.

**Method.** Five independent reviews, each reproducing its findings against the shipped 1.12.1 build in scratch repositories and listing what it checked and found clean:
- **P — packs, gc and the store lock:** hostile packs, local and in a file:// remote; gc killed at 148 points; reachability against fsck's; the lock under every kind of planted file.
- **S — serving and remote URLs:** `--repos` name resolution under every traversal spelling and under races; eviction, its resources and its correctness; base-path URLs on the wire; the read API across repositories.
- **L — local write paths of 1.8.0–1.12.1:** stash, merge, reflog, prune, add, against the CLAUDE.md invariants (`materialize_target_safe`, `sf_*`, existence by `lstat`, patra write status, fsck roots).
- **G — the `.git/` read path:** the "sit writes nothing in `.git/`" rule by full before/after snapshots; alternates; relaxed names; widths; a differential against git on real repositories.
- **X — external research:** advisories in git, libgit2, go-git, gitoxide, JGit, dulwich, Gitea / Forgejo / Gogs / GitLab / cgit / git-daemon / git-http-backend, matched to the new surfaces only (1.7.6 swept January 2025 → October 2026 broadly).

Two more came from the closeout's own refactor pass (**K1, K2**). Every finding was reproduced before its fix and re-run after it with the reviewer's script; integration section 44 holds a regression test for each that can be one (36 of its 47 assertions fail on 1.12.1), and `test_1122_closeout` and `fuzz_clone_names` cover the new pure functions.

**A sixth review read the finished fix diff (K3–K9),** as 1.7.6's did, and found seven mistakes in the first cut. All were fixed and re-run before release:
- **K3:** the lock file's new `O_NONBLOCK` is not named by agnos's stdlib, so `cyrius build --agnos` failed, for sit and for thoth's bundle. It is now added only where the target has it.
- **K4:** S4's fix missed two routes. A ref link through a linked directory (`d → elsewhere`, `evil → d/main`) still reached out, and so did a `refs/heads` that was itself a link. The refs walk now enters only real directories, and a link's target is checked component by component.
- **K5:** G5's line cap missed one 8 MB alternates line, whose path was still kept per open. And `eprint3`, now sanitizing, copied every message onto the heap. Alternates paths are freelist memory, freed unless listed, and longer than 4,096 bytes is skipped. `write_sanitized` works through a stack buffer.
- **K6:** with `sit_packs` skipping an `.idx` whose `.pack` is not a regular file, gc no longer removed such an `.idx`. The sweep now removes any pack file without a regular-file partner.
- **K7:** an `else` booked an object that failed to verify as written (latent: the function then failed).
- **K8:** `reflog expire` / `delete` lacked the identity check L6 gave appends, so two concurrent rewrites could still lose an append.
- **K9:** a FIFO at a top-level refs directory still hung fsck's walk. It was not new.

The review also confirmed what held: commits and tags byte-identical to 1.12.1 (signatures verify across both builds), `store_enter` under single-repository and `--repos` serving with gc cycles and evictions, every caller of the new lock return, the prune verdict codes, and owl (cyrius 6.6.2) and thoth building against the regenerated read bundle.

**Headline: three ways to reach outside the repository, all on paths that checked once and then trusted.** A clone named its directory after a server-chosen URL segment, so `…/x/.git` wrote the server's tree, `config` included, into `./.git` (X1). `status` and `diff` read a tracked path through a symlinked directory, so a checkout could make `sit diff`, and what owl and thoth get from `sit_diff_path`, print a file from outside the worktree (G1). And `sit serve --repos` resolved a name once, then served it from the cached path, so a directory swapped for a symlink after its first request served, and took pushes into, a repository outside `<dir>` (S3). Below those, the pattern of the last two audits held: data loss with exit 0 where one path skipped a check its sibling made — `fsck --prune` judging a commit by its own date while a kept commit sat on it (L1), an unreadable ref read as no ref (L2), gc keeping a pack it had not verified (P1).

## HIGH

| # | Defect | Repro on 1.12.1 | Status |
|---|---|---|---|
| X1 / S2 | `sit clone` named its directory after the URL's last segment, `.git` / `.sit` / `.ssh` included | `sit clone http://host/x/.git` → "cloned … into .git", the server's tree (a `config` with `core.fsmonitor`) in `./.git`; the next `git status` ran it | **Fixed** |
| G1 / X4 | `status`, `diff` and `sit_diff_path` read a tracked path through a symlinked directory | a checkout ships `keys` as a link to a directory outside it, HEAD tracks `keys/key`: `sit diff` printed the outside `key`; so did owl's `sit_diff_path` | **Fixed** |
| S3 / X3 | `--repos` checked a name's path once, then served the cached path and lock descriptor | swap `served/team` for a symlink after one request: a clone returned the outside repository, a push wrote a branch into it, and a gc there ran during a request | **Partial** |

**X1.** The derived name now skips a segment that is `.`, `..` or spells `.git`, `.sit` or `.ssh` (in any case, with HFS-ignorable codepoints, or as an NTFS short name) for the one before it, as git names a clone of `…/proj/.git` "proj"; with no segment left, the host. A target, given or derived, whose last component spells one is refused. The spelling check is `name_spoofs_dotdir`, now shared by tree entry names and clone targets. `.ssh` is guarded too: cloned from `~`, `…/x/.ssh` would have planted the server's `authorized_keys`.

**G1.** A worktree read goes through `wt_readable` (util.cyr), which refuses a path with a symlinked directory above it, as git's `has_symlink_leading_path` does: status reports the file deleted and diff shows its removal, on both backends and through the API. The write paths have refused such a parent since 1.6.4; the read paths never asked.

**S3.** A kept repository is checked again on every request (`_serve_repo_kept`: at most 17 `lstat`s and no allocation), and must still be the directory it was by device and inode. A repository that fails either is closed and resolved afresh, with a new store handle and lock descriptor: that also covers a repository replaced by another real directory (restored from a backup), which was served through the old one's handle. **Partial:** a swap between the check and the opens inside one request still races (S3b reached the outside repository in about 60 of 300 rounds when every request re-resolved). Closing that needs every open made relative to a directory descriptor opened `O_NOFOLLOW` from `<dir>` — roadmap, 1.13.x. The attacker needs write access to a directory under `<dir>`.

## MEDIUM

| # | Defect | Status |
|---|---|---|
| S1 / P2 | `--repos`: a repository evicted from the 64, then gc'd, was served from its old pack list — its packed objects 404'd and clones failed until a restart | **Fixed.** `store_enter` compares the store file's identity on every session, against the file seen at the last one, not only while a handle is open; on a change it drops that root's pack list (`sit_packs_forget`) and the mappings of packs that are gone. No mapping of a deleted pack survives (2 per gc'd repository before) |
| P1 | gc kept an existing same-name pack it had never verified, deleted the copy it had, then compaction dropped the rows holding the only good copies | **Fixed.** The verified pair is renamed over a pack of the same name. An `.idx` whose `.pack` is gone, and a pack damaged beside intact rows, both come out whole (were: every object lost, exit 0) |
| L1 / X2a | `fsck --prune` deleted a dangling commit past the window on its own date, even when a kept dangling commit or a tag sat on top of it | **Fixed.** Whatever a kept dangling object reaches is kept, of any type — git's "keep what a recent object reaches". The kept set is seeded by in-window and undatable commits, tags, and undatable trees |
| X2b/c | `--prune` ran under the shared lock, beside a fetch or a served push; objects that had arrived but that no ref named yet were deleted, and the server then moved the ref onto a hole | **Partial.** `--prune` takes the store lock exclusively, as gc does, so it refuses while a command or a request is in progress. A push spans requests, though, and the server's ref update checks only that the tip is a commit: a receive-side connectivity check (git's `check_connected`) is roadmapped |
| L2 | an unreadable ref, refs directory, stash ref or reflog was read as absent — not a root — and `--prune-now` deleted what it named, exit 0 | **Fixed.** The roots are collected by `lstat`; one that exists and cannot be read is named on stderr and counted (`_fsck_roots_unread`), and `--prune` refuses while any is. The in-progress guards (MERGE_HEAD, …) ask `lstat` too. The refs walk is sit's own (`_fsck_walk_files`), since `dir_walk` skips an unreadable directory in silence and `dir_walk_checked` is newer than owl's and thoth's toolchains |
| L3 | `sit stash` recorded a tracked file it could not read as deleted, then wrote HEAD's copy over the edit | **Fixed.** Presence by `lstat`, so the 1.6.4 A14 refusal runs: "cannot save … — nothing stashed" |
| G3 | `log` and `show` followed a merge's **last** parent: the mainline vanished from `log`, and `show` diffed a merge against the merged-in branch | **Fixed.** `parse_commit_body`'s single-parent slot holds the first parent; only `cmd_log` and `cmd_show` read it |
| S4 | a served repository's `.sit/packs/*`, refs, or `refs/heads` itself linked into another repository were served as its own | **Fixed.** `sit_packs` lists regular files only. The refs walk enters only real directories, and follows a link only when it stays in the refs tree (relative, no `..`, through real directories to a regular file), so an in-tree alias still lists (K4) |
| G4 | a tiny crafted tree DAG (5 levels × 16) expands to ~1M paths: `sit status` took 8 s and 824 MB, the API 42 s and 3.3 GB over three calls | **Deferred.** Bounded (2M nodes) and fails closed; a lower ceiling for the status path, or not expanding the HEAD tree (1.14.0's DIRC reader), is roadmapped |
| S5 | `--repos` past 64 repositories leaks ~4.4 KB of bump heap per store reopen, nearly all inside `patra_open` (its WAL path) and `CREATE TABLE` | **Deferred.** A patra ask (freelist the WAL path) is on the roadmap's upstream list; the per-request arena does not cover it |

## Checked and found clean

- **Hostile packs** (P): truncated packs and idx files, bad fanouts, offsets past the end or into the header, 8-byte offset abuse, OFS deltas at 0, before the start or at 2⁶², REF deltas in a sit pack, size mismatches, a 256 MiB declared size, a 17 MiB commit, a zero count, and symlinked packs in a remote at `/proc`, `/dev/zero`, a FIFO: none crashed or hung; reads fail closed, fsck flags each, gc refuses, clone refuses. Content that does not hash to its id is refused by every transfer path through `_object_verify`.
- **gc crash points** (P): SIGKILL at 148 syscall stops and write points on two fixtures; after every kill fsck was clean, every id read, a second gc and a commit worked (the one residue was P4). Disk full at every stage: refused, nothing lost.
- **gc's reachability** equals fsck's: refs, reflogs, the index, stash, tags, remote refs, MERGE_HEAD; unreached objects are loosened, never deleted.
- **The lock file** as a symlink, a directory, a FIFO or mode 000: commands run unlocked, gc refuses, nothing hangs or is created through a link. The lock is close-on-exec in children.
- **`--repos` names** (S): every traversal spelling (raw, `%2e%2e`, `%252e`, `%2f`, backslash, `%00`, `//`, `/./`, 17 segments, 256-byte segments, hidden names, an embedded second `/sit/v1/`) is a 404. 1,500-round stress over 70 and 100 repositories with gc and commits mixed: no cross-repository read. All three serve loops route through `serve_handle_request`.
- **Base-path URLs on the wire** (S): no request-line or header injection; CR / LF / NUL refused; IPv6 literals refused; the path is sent verbatim after trimming.
- **The read API across repositories** (S, G): `.sit` and `.git` mixed, A → B → A, a failed open in between: per-repository status correct, no state shared.
- **sit writes nothing in `.git/`** (G): full before/after snapshots (type, size, mtime, ctime, mode, link target, SHA-256) over every read command with every option, sha1 and sha256, clean and dirty: identical. Every write command refuses.
- **Terminal output in git mode** (G): status, diff, show, log, reflog sanitize hostile names, authors, messages and reflog lines (the alternates warning was the one gap, G2).
- **Short ids, widths, `@{N}`** (G): ambiguity across loose, packs and alternates matches git; every read-path width literal reviewed; malformed selectors fail closed.
- **Differential against git** (G): `log` / `log --graph` against `git rev-list --first-parent` (181 commits, both formats), `show --stat` against `git show --numstat` (181 × 2, no mismatch), and randomized worktree edits against `git status --porcelain` / `git diff --numstat` (6 seeds × 2 formats): identical, beyond the documented differences (git's index is not read).
- **1.8.0's local paths** (L): a conflicted three-way pop keeps its entry and blocks what it should; `reflog expire --all --expire=now` keeps every stash entry (sit's stash is a parent chain, not a reflog — git's same command empties `git stash list`); `@{<time>}` matches git on ties, before-first, future, backwards and empty logs; MERGE_MSG survives a 131 KB message and is cleared on every exit path but the one L7 found.
- **External advisories** (X), not applicable: go-git CVE-2026-34165 / CVE-2026-25934 / GHSA-w5pp-99ch-qj29 / CVE-2023-49568 / CVE-2025-21614, libgit2 CVE-2018-10887 / 10888, idx v2 large offsets, the same-name repack class, the gc-versus-push race (gc never deletes), CVE-2024-32020 / 32021 / CVE-2022-39253 / CVE-2023-22490 (file:// clones parse and verify, never link), gitoxide CVE-2025-31130, git-daemon and git-http-backend path handling, cgit CVE-2018-14912, GitLab CVE-2023-2825, Gogs / Gitea path traversal, CVE-2020-5260 / 11008, CVE-2024-50349 / 52006, CVE-2025-48384, CVE-2017-1000117, CVE-2022-24765, CVE-2024-32004, CVE-2023-23946, config-driven execution (sit reads none: no hooks, fsmonitor, pager, drivers or attributes), libgit2 CVE-2024-24575 (`@{` parsing).

## Deferred → roadmap

- **1.13.x:** `openat`-relative repository resolution under `--repos` (S3's residual race); a receive-side connectivity check on ref updates (X2c); reading and expiring reflogs past 64 MiB (L5); the index update's per-row cost for large `add`s (L10); a status-path ceiling on tree expansion (G4).
- **Upstream asks** (sit roadmap, "Upstream asks"): patra — a freelisted WAL path in `patra_open` (S5) and `O_CLOEXEC` on its file descriptors (P7); cmdit — completion scripts that keep file names whole, and fish file completion (L11).
- **Unscheduled:** upper-case hex ids (G7); bare `@{N}` and the empty-log fallback (G8); gc trimming mid-tree (P9); a depth-aware delta base cache (P10); a store of one object per pack (P6's remainder).
