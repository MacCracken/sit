# Security + correctness audit — 2026-08-17 (v1.3.7)

A full P(-1) hardening pass over the whole tree, run after the v1.3.6
toolchain/dependency refresh. Scope: every parser that touches data sit does not
control, the buffer/syscall/exec surface, path-traversal defenses, a dead-code
sweep, and the test suite's own hygiene.

**Headline: the `.git/` packfile reader (v1.2.0, `src/git_pack.cyr`) was the one
module in the tree with no fuzz target, and it is where every serious finding in
this audit landed** — three reproducible SIGSEGVs and a heap-memory disclosure,
all reachable from a repository the user merely *reads*. Both classes are fixed,
both are pinned by a new deterministic corpus, and the coverage gap that hid them
is closed with two new fuzz harnesses.

## Threat model (why `.git/` read-mode is exposed)

`.git/` read-mode exists so consumers — owl's gutter markers, thoth's status bar
— can report on **arbitrary real-world git repositories** on the user's disk
without shelling out to `git`. Those repositories are routinely cloned from
remotes the user does not control. So the bytes in `.git/objects/pack/*.{idx,pack}`
are **attacker-controlled input on a read-only, no-privilege path** — the user
never runs a write command, never types a password, and reasonably believes
"sit is only looking at it".

That makes a crash a denial of service against any consumer that opens an
untrusted repo, and an out-of-bounds read an information disclosure into output
the user is shown.

### 1 — HIGH: `_git_idx_lookup` trusts the `.idx` table geometry (memory safety)

`src/git_pack.cyr`. The v2 `.idx` reader validated only the 4-byte magic, the
version word, and `len >= 1032` (header + fanout). **Every table address after
that was computed from numbers inside the file**:

- `N = _be32(fanout + 255*4)` — the object count, unbounded.
- `lo` / `hi` from the fanout — used directly as binary-search bounds, so
  `oid_table + mid * rawlen` could land anywhere.
- `off_table = oid_table + N*rawlen + N*4` and `large_table = off_table + N*4` —
  both derived from the unbounded `N`, then indexed and dereferenced.

A `.idx` whose fanout claims ~10⁹ entries drives the first `_memcmp_n` gigabytes
past the mapping. **Reproduced as a SIGSEGV three different ways** (`huge_fanout`,
`huge_N`, `large_offset_oob`) on nothing more than:

```bash
sit cat-file <any-hash>
```

**Fix**: derive the maximum possible `N` from the actual file length
(`N > (len - 1032) / (rawlen + 8)` → reject), require the fanout to be monotonic
within `[0, N]` (`lo <= hi <= N`), and bound the large-offset entry against `len`
before `_be64` reads it — the large-offset table sits *after* the size gate, so
it needs its own check.

### 2 — HIGH: `_git_apply_delta` literal opcode reads past the delta (info leak)

`src/git_pack.cyr`. The delta interpreter's literal (insert) opcode copies
`op & 0x7F` bytes out of the delta stream. It bounds-checked the **destination**
(`op_out + lit > result_size`) but never the **source** — nothing verified that
`cur + lit <= delta_len`.

A delta ending in a bare `0x7F` opcode therefore copied **127 bytes of whatever
followed the delta buffer on the heap** into the reconstructed object. Because
the attacker also picks `result_size`, they can make `op_out == result_size`
exactly, so the function returns **success** and sit prints the bytes:

```
$ sit cat-file aaaa...aaaa | xxd
00000010: 0000 0000 4006 00b7 8b7f 0000 0500 0000
                   ^^^^^^^^^^^^^^^^^^^ live heap pointer (0x7f8bb7000640)
```

That is an ASLR-defeating pointer disclosure plus adjacent allocator metadata,
delivered through a read-only command, from a repo the user only browsed.

**Fix**: bound the literal against `delta_len` before the `memcpy`, and bound the
COPY opcode's whole operand run (`_delta_op_bytes(op)`) before `_next_byte`
consumes any of it.

### 3–7 — Hardening on the same parser (no demonstrated exploit)

These were found by reading, are real missing guards, and are fixed — but the
corpus cases written for them pass on the **pre-fix** binary too, because an
earlier error path (usually `zlib_decompress` rejecting a malformed stream)
happened to catch them first. They are recorded as defense-in-depth, **not** as
demonstrated vulnerabilities, and the distinction is deliberate: an audit that
claims unproven exploitability is worth less than one that separates the two.

- **Unbounded varints** — `_pack_obj_header`, `_ofs_varint` and `_delta_varint`
  looped on the continuation bit with no length argument at all, so a final byte
  with the high bit set walks off the buffer until it finds one without. All
  three now take the buffer length, cap the continuation run at
  `_PACK_VARINT_MAX = 10` bytes, and reject a wrapped (negative) accumulator —
  which also closes a path where a padded varint could overflow `size` negative
  and slip past the `> _PACK_MAX_OBJ` gate.
- **`_git_pack_obj` offset** — the pack offset comes from the `.idx` and can
  reach 2⁶³ via the large-offset table; it is now required to satisfy
  `12 <= offset < plen` before it becomes a load address.
- **Negative-length inflate** — a header that consumed the buffer left
  `plen - body` zero or negative, handed straight to `zlib_decompress` as a
  length. All three call sites now check `body < plen` first.
- **OFS_DELTA distance 0** — made an object its own delta base; bounded only by
  the 64-frame depth cap. Now rejected outright.
- **REF_DELTA base oid** — `hex_encode(pdata + cur, rawlen)` read 20/32 raw bytes
  with no check that they were inside the pack.

### 8 — LOW: `refs/remotes/` guard off by one

`src/serve.cyr:762`. The guard read `rname_len >= 12` before
`memeq(rname, "refs/remotes/", 13)`. The read stayed **in bounds** (the buffer is
`rname_len + 1` and byte 12 is the NUL terminator) and the comparison still
failed correctly, so there was no bug in behaviour — but the guard read as an
overread and would become one if the buffer ever stopped being NUL-terminated.
Tightened to `>= 13`. Found by a mechanical scan for guard-vs-compare length
mismatches across the tree; this was the **only** instance.

### 9 — Process: the pack parser had no fuzz target

CLAUDE.md requires "fuzz every parser path". Seven harnesses existed
(`zlib_decompress`, `hash_data`, `hex_decode`, url validators, ssh-url parser,
want-frame decoder, reflog index) — and **none covered `.idx` or pack decoding**,
the newest and least-exercised binary parsers in the tree. The coverage gap and
the defect cluster were the same place.

Closed with two harnesses in `tests/sit.fcyr`:

- `fuzz_pack_varints` (500k rounds) — random buffers, cursor started at random
  in-range offsets *including the last byte* so a trailing continuation bit is
  exercised every round, plus a past-the-end cursor that must fail closed.
- `fuzz_apply_delta` (200k rounds) — random delta streams against a fixed base,
  plus zero-length and zero-base-length calls.

⚠ **Honest limit**: without ASAN, fuzzing catches *crashes*, not a 127-byte
overread into mapped heap. Finding 2 would likely **not** have been caught by the
fuzz harness alone — it is pinned by the deterministic corpus below, which
asserts on the leak directly (a delta case that exits 0 is a failure).

### 10 — Process: `run.sh` shadowed its own `$ROOT`

`tests/integration/run.sh:130` assigned a commit hash to `ROOT`, clobbering the
repo-root path set at line 13. Latent for as long as nothing used `$ROOT` after
that point — it broke immediately when the new corpus step did. Renamed to
`ROOT_COMMIT`.

## New regression coverage

`tests/integration/hostile_pack.py` (+ `packlib.py`) — **11 hostile packfile
fixtures**, wired into `run.sh` as scenario 10 (guarded on `python3`).

The corpus opens with a **positive control** that builds a valid pack plus a real
OFS_DELTA and asserts sit reconstructs it byte-for-byte. This is load-bearing:
the first draft of this corpus scored **7 false passes** because the fixtures were
malformed and bounced off an earlier error path without ever reaching the parser.
A hostile-input test that never reaches the code it targets pins nothing, and
looks identical to one that does.

Proven non-vacuous by A/B against a pre-fix binary:

```
                          pre-fix (v1.3.6)   post-fix
  positive control        PASS               PASS
  huge_fanout             FAIL  exit=-11     PASS  exit=1
  huge_N                  FAIL  exit=-11     PASS  exit=1
  large_offset_oob        FAIL  exit=-11     PASS  exit=1
  delta_literal_overrun   FAIL  LEAK 127B    PASS  exit=1
  (+ 7 hardening cases)   PASS               PASS
```

## Areas reviewed and found clean

- **Command execution** — no `sys_system` anywhere in the tree. `cmd_owl_file`
  uses `exec_vec` with an explicit argv (owl path + a tempfile path built from a
  validated hex prefix); no user-controlled string reaches the argv. The ssh
  transport's raw `sys_execve` is deliberate and documented at the call site.
- **Path traversal** — `tree_entry_name_valid` rejects `.`, `..`, `/`, `\`, `:`,
  control bytes, NUL, DEL, and trailing space/dot; `tree_flat_path_valid` rejects
  absolute paths and empty/consecutive segments and validates every segment
  through the former. The S-03 hardening holds.
- **`parse_tree`** — bounds every field against `body_len` before reading,
  including `nu + 1 + rawlen > body_len` before the hash read. Clean.
- **`_git_read_loose`** — length-guarded, 16 MiB decompression ceiling with a
  retry, NUL scan bounded by `dlen`. Clean.
- **`_git_packed_ref_lookup`** — exact line-length equality check before any
  field read. Clean.
- **Push trust boundary** (`_serve_rehash_and_insert`) — decompresses, verifies
  the framing type against the claimed type, recomputes the SHA-256 over the full
  framed bytes and refuses on mismatch. A client cannot store an object under a
  hash it does not hash to. Clean.
- **Ref-write authorization** — `refname_valid` plus an explicit
  `refs/heads/` / `refs/tags/` allowlist plus a `refs/remotes/` denial plus
  denyCurrentBranch. Clean (see finding 8 for the cosmetic guard).
- **`memeq` literal/length agreement** — mechanically scanned; zero mismatches.
- **Stack buffers** — every `var buf[N]` inventoried against its writes; the hex
  buffers (`[72]` for 64 hex + NUL) and `_git_object_path`'s `[96]` (needs 79)
  all carry correct headroom.

## Dead-code audit

Five functions have no in-tree caller. **All five kept**, none are waste:

- `sit_repo_branch`, `sit_repo_status` — **public API** consumed by owl/thoth
  through `dist/sit.cyr` ([ADR 0009](../adr/0009-public-api-contract.md)).
- `build_merge_commit` — intentional thin wrapper (CLAUDE.md records this).
- `sf_mkdir`, `sf_stat` — members of the `sf_*` path-prefixing family.
  **Considered for deletion and rejected**: an asymmetric family is a trap. The
  next person needing a prefixed stat would find no wrapper and reach for raw
  `xstat` / `sit_mkdir` — exactly the unprefixed-path and Linux-shaped-syscall
  bug class the seam exists to prevent and that 1.3.4 spent a release fixing.
  DCE strips both from the binary, so the only cost is the source lines. The
  rationale is now recorded at the definition site.

## Refactor

- `_serve_rehash_and_insert` scanned the framing header **twice** for the
  type/length separator — once to prove a space existed, again to recover its
  index, because the first pass clobbered the cursor to force loop exit.
  Consolidated to a single flag-guarded pass with the index in its own slot.

## Cleanup sweep

- **`src/lib/` removed** — 3.4 MB, 82 files, untracked and gitignored, last
  written in May. Pre-6.x artifacts (it still carried `base64.cyr` / `bigint.cyr`,
  folded into `bayan` by cyrius 6.x) for modules sit does not even depend on
  (`agnosys`, `yukti`). Unreferenced by any include, manifest, or workflow. An
  empty `src/build/` went with it. `src/` is now exactly the 22 source files.
- **15 files reformatted** to the 6.5.x formatter. 13 were untouched by this
  release — pre-existing drift, verified present at the 1.3.6 tag, and the reason
  `cyrius audit` was failing its fmt gate. The sole change is `#ifdef` / `#else` /
  `#endif` indented to the enclosing block.

  ⚠ **Verified rather than assumed, because sit is the wrong project to assume
  on.** These directives select **syscall ABI shape** between AGNOS and Linux
  (`sit_mkdir` / `sit_rmdir`, the lstat degradation in `validate.cyr` /
  `serve.cyr`, the ssh spawn gate in `wire_ssh.cyr`). A column-sensitive
  preprocessor would silently pick the wrong branch, and **a Linux test run could
  not detect it** — Linux still takes the Linux branch, so the whole suite stays
  green while the AGNOS binary is quietly miscompiled. That is precisely the bug
  class 1.3.3, 1.3.4 and 1.3.5 each spent a release closing. Checked by building
  **both targets before and after** and comparing: `sha256` identical on Linux
  **and** on `--agnos`, DCE included. Cosmetic, safe.
- **`.gitignore`** gained `__pycache__/` / `*.pyc` for the new Python fixtures.

## Verification

- 282 unit / **70 integration** (was 58; +12 from the hostile corpus) / 9 fuzz
  harnesses (was 7) / lint 0 warnings / `cyrius audit` / benchmarks — all green.
- Benchmarks vs the pre-audit baseline: **no regression**, max |delta| 7.0% on a
  sub-microsecond measurement (`sha256-64B`, 676ns → 723ns) on an unpinned box.
  No benchmarked path was touched by this pass.
- `--agnos` builds clean with and without DCE.
- Both dist profiles regenerated; no public-API change.

## Result

Two genuine memory-safety defects on the untrusted-input path, both reachable
from a read-only command against a repo the user merely opened, both fixed and
pinned by a corpus proven to catch them. Six further missing guards on the same
parser closed as hardening. The fuzz gap that hid them is closed.

The lesson worth carrying: **the defect cluster and the coverage gap were the
same place**, and the module was three minor versions old. New parsers need their
fuzz target in the release that introduces them, not the audit that follows.
