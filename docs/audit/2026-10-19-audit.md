# Security + correctness audit — 2026-10-19 (v1.6.4, closes 1.6.x)

The P(-1) hardening pass that closes the 1.6.x line. **Scope:** everything that changed since the last full audit (2026-08-18, v1.3.8). That is about 3,700 changed lines across 27 files and fourteen releases, 1.4.0 → 1.6.3:
- `sit tag -a/-s`, `mv`, `describe`
- `cherry-pick`, `revert`, `stash`
- octopus merge, `blame`, `rebase`
- TLS trust hardening and mTLS
- delta generation
- the diff-based index rewrite

That audit's deferred items were re-checked too.

**Method.** Five independent auditors, one per area:
- history rewriting
- refs / tags / signing
- index / diff / worktree
- network
- storage / packs / public API

Each auditor reproduced its findings in scratch repos against the built binary, traced the upstream guards that might already block them, and listed what it checked and found clean. Every finding was then re-verified before a fix:
- against both the 1.6.3 and the 1.6.4 binaries, using the same repro scripts
- red/green, with regression tests that fail on 1.6.3

External research (P(-1) step 4) added two classes the area audits had not covered.

**Headline: the worst defects are data loss in ordinary use, not exploits.** Every one of these succeeded with exit 0 on 1.6.3:
- an uncommitted edit wiped by `cherry-pick`
- a line silently dropped by a clean three-way merge
- the clean half of a conflicted merge lost at commit time
- a revert undone by an octopus merge
- a week of commits rolled back by `stash pop`
- a 70 MB file truncated to 6 bytes by `checkout`
- a shallow clone's history deleted by `fsck --prune-now`

As in 2026-08-18, the code that looked boring held the worst bugs.

## HIGH — all fixed

| # | Area | Defect | Repro on 1.6.3 |
|---|---|---|---|
| A1 | history | cherry-pick, revert, rebase, octopus and stash pop overwrote uncommitted work | `echo WORK > b.txt; sit cherry-pick side` → rc 0, b.txt reset |
| A2 | merge | line merge dropped theirs' insert at the start of ours' replace | base `a b c`, ours `a B c`, theirs `a x b c` → clean `a B c` |
| A3 | merge | conflicted merge / pick / rebase never staged the clean half | resolve, `sit add`, `sit commit` → other side's clean edit lost |
| A4 | merge | octopus used the previous branch as the merge base | `merge b1 b2` re-applied a change main had reverted |
| A5 | stash | `pop` restored the whole snapshot over later commits | stash, commit, pop → the commit undone and staged |
| B1 | index | `sit add` staged `./a`, `..`, absolute and `.sit/` paths verbatim | `sit add ./a.txt` → committed into a `.` subtree no reader sees |
| B2 | status | a file it could not hash counted as unchanged | 70 MB edit → `status` clean → `checkout` overwrote it (6 bytes) |
| B3 | checkout/pull/clone | materialize failure ignored; HEAD moved anyway | untracked dir in the way → "switched", index on the old tree |

| D2 | fsck | walk stopped at `.sit/shallow` even with parents present | `clone --depth 1; fetch; fsck --prune-now` → history deleted |
| D3 | git mode | every object read re-read every `.idx` (never freed) | `sit_repo_status` on 12k files: 4 GB RSS (owl / thoth in-process) |
| E1 | refs | ref / reflog / HEAD writes followed symlinks in `.sit/` | `refs/heads/main -> ~/f`: `sit commit` truncated ~/f |

### How each was fixed

- **A1 / B6 / B8 — one preflight, every caller.** `materialize_target` now has two forms:
  - `materialize_target` stays the forced form, for `reset --hard` and the abort/restore paths.
  - `materialize_target_safe(hex, dirty_checked)` refuses before writing anything if any of these holds:
    - the tracked tree is dirty
    - an untracked, non-ignored file would be overwritten
    - an untracked file sits inside a directory the target turns into a file
    - an untracked file occupies a path the target needs as a directory
    - any path to be written or removed lies beyond a symlink (B8)

  Checkout, merge (fast-forward / three-way / octopus), pull, clone, cherry-pick, revert, rebase and stash pop use the safe form. cherry-pick, revert and rebase also refuse a dirty tree before any conflict-path write.
- **A2.** `hunks_overlap` treats a pure insert at the start of the other side's replace as a conflict, symmetrically (git conflicts there too).
- **A3.** A new `_apply_conflicted_merge`, shared by merge and cherry-pick/revert (and so by rebase), writes the worktree and then stages the index:
  - clean paths at their merged content
  - conflicted paths at HEAD's version until `sit add`
  - clean deletions removed from the worktree as well

  `MERGE_HEAD`, conflict-file and marker write failures are now reported.
- **A4.** `_octopus_base` takes the best merge base against every commit merged so far (git's octopus semantics) and refuses a criss-cross. Branches already contained in HEAD or an earlier argument are skipped instead of becoming redundant parents.
- **A5.** `stash pop` requires HEAD to be the stash's base commit and restores through the safe materialize. A three-way pop is on the roadmap.
- **B1.** `sit add` strips leading `./`, then requires `tree_flat_path_valid` and the 255-byte index path limit.
- **B2.** In `is_dirty`, `status` and the worktree-vs-index check, unknown means changed.
- **B3 / B9.** checkout, pull and clone check the result and materialize *before* moving HEAD; pull had the ordering bug 1.5.1 fixed for reset and merge. `rewrite_index` is transactional (B7) and its failure is a materialize failure.
- **B4.** Emptied directories are removed after stale files (`_rmdir_empty_parents`), an empty directory at a file path is cleared, and `sit rm` removes the directory it empties.
- **B5.** `sit add` refuses files above `SIT_MAX_BLOB` (16 MiB minus framing), the read ceiling.
- **C1.** `db_object_read_raw` and `_decompress_raw_into` hand back freelist memory, and the object, `/want` and PUT handlers free it per request. Measured: start 6.6 MB → 7.0 MB after 100 GETs and 20 `/want`. A residual of about 3 KB per request remains (header / SQL bump allocations) and is deferred: it needs a request arena.
- **D1.** `SIT_MAX_INFLATE_RATIO` 1000 → 1100, above deflate's ~1032:1 ceiling. It now rejects no valid stream; the 16 MiB ceiling is the bound.
- **D2.** A boundary commit's parents are walked when present and only exempt from "missing" when absent.
- **D3.** `.idx` and `.pack` files are cached per path. The old cache held one pack, so two packs read alternately thrashed it the same way. 3,000-file git repo: peak RSS 255 MB → 13 MB.
- **E1.** `sf_write_all` for repo-relative paths:
  - refuses a symlinked parent (`-ELOOP`)
  - removes whatever is at the path (a symlink itself, not its target)
  - creates the new file `O_CREAT|O_EXCL`, which also refuses a symlink planted in between
  - loops on a sit-owned `sit_write_full`

  `sf_append_locked`, `sf_unlink`, `sf_rename` and `ensure_parent_dirs` refuse symlinked parents too. `O_EXCL` rather than `O_NOFOLLOW`: the latter differs on aarch64, and cyrius 6.6.2 (owl's pin) does not name it.

## MEDIUM

**Fixed:**
- **W1** (pre-audit): `_wire_io_send`'s plain path made one `sock_send` and dropped the count, so a short write silently truncated a request or response. It now uses `sock_send_all`, and every client caller checks the result. On the server, a failed TLS response write closes the keep-alive connection rather than serving a desynchronised stream. The ssh pipe writes got the same loop.
- **X1** (external research, Gitea CVE-2026-95106 class): a tree naming `a` twice made `sit show` list both blobs while checkout wrote the second, and fsck called it clean. `parse_tree` now requires strict git order, which rules out duplicates (and git's `treeNotSorted`). Plain `fsck` reports dropped entries and exits 1. `build_tree` refuses to write a duplicate name (A11).
- **A6**: `REBASE_ORIG` now records the branch, and `--abort` / `--continue` refuse on any other branch. A `checkout main` mid-rebase followed by `--abort` used to reset main to the feature tip.
- **A7**: `REBASE_ORIG` is validated as hex plus a readable object; the todo must be exact `<64 hex>\n` records naming readable objects. A NUL-filled `REBASE_ORIG` used to empty the worktree on `--abort`, and one CR in the todo silently dropped the rest of the branch.
- **A9**: `fsck --prune` refuses while `REBASE_ORIG`, `CHERRY_PICK_HEAD` or `REVERT_HEAD` exists. `sit commit` clears the latter two.
- **B8**: see A1.
- **B9**: see B3. pull now materializes before moving HEAD, so files deleted upstream leave the worktree.
- **B10**: the `**` scan in `_wildmatch` charges the step budget per offset tried. The auditor's 100-line hostile `.sitignore`: 99.9 s → 1.3 s.
- **B11**: the lstat guards read `st_mode` at the per-target `STAT_MODE` offset. A hardcoded 24 read `st_uid` on aarch64, which made every symlink guard there a no-op; verified under qemu.
- **B12**: `-U0` hunk headers start an empty side at the line before the change (`@@ -10,0 +11 @@`), matching GNU diff. `patch` round-trips.
- **C2**: `serve --tls` arms a 60 s handshake deadline and per-request / per-response deadlines (sandhi's plain-loop budget). A pre-handshake trickler held the single-threaded loop indefinitely; a second client is now served after 59 s, where 1.6.3 never served it.
- **D4**: fsck reads a commit's `tree` through `parse_commit_body`, like every other reader. It accepted `tree` on line 1 only, so a commit with `parent` first had its tree pruned.
- **D5**: delta reconstruction is held to 16 MiB (it was 256 MiB per chain level).
- **D7**: the worktree walk lstat's through the repo-root seam (the deferred 2026-08-18 item, finished).
- **E2**: HEAD's symref target must start with `refs/`. `ref: objects.patra` made the next commit overwrite the object database.
- **E3**: `verify-tag` prints the *signed* tag name and target, and refuses a tag object found under a different name (signed-release replay / rollback).
- **E4**: `resolve_commit_hash` requires a commit after peeling, and materialize refuses an unreadable target instead of treating it as an empty tree (which deleted every tracked file).

**Partial:**
- **B7**: `rewrite_index` is one transaction with rollback, its callers check it, and `sit add` refuses paths over the 255-byte index column. The column limit itself remains.

**Deferred** (roadmap, *Deferred from the 2026-10-19 audit*):
- **A8**: rebase walks first parents only.
- **C3**: the bearer token is not bound to a remote. This needs per-remote credential config.
- **D6**: git packs over 64 MiB or with deltas deeper than 64 are unreadable.

## LOW

**Fixed:**
- **A10**: cherry-pick, revert, rebase steps, `--continue` and `--abort` write reflog entries (invariant 005).
- **A11**: see X1.
- **A12**: binary content (a NUL in the first 8000 bytes) is never line-merged.
- **A13**: `blame` warns when a diff refuses, instead of silently mis-crediting.
- **A15**: `CHERRY_PICK_HEAD` and `REVERT_HEAD` are cleared by commit, and octopus no longer adds duplicate parents.
- **C4**: `http.sslVerify` is parsed as a strict, case-insensitive boolean, and an invalid value refuses to connect. `TRUE` / `on` used to mean TOFU.
- **C5**: ssh ref advertisements are hex- and `refname_valid`-checked.
- **C6**: `do_fetch`'s walk-cap abort returned the pointer `1`, which crashed pull and clone.
- **C7**: ssh object reads check the type (0..2) and length.
- **C8**: `/want` grows its buffer to the body ceiling instead of answering 413 for any object over about 128 KiB.
- **C9**: covered by E1.
- **D8**: git-mode object ids are hex-gated before the backend dispatch. A crafted `tree` value used to open a file outside `.git/objects`.
- **D9**: fsck accepts any ref the resolver accepts as a root, so a ref with a trailing space is no longer pruned.
- **D10**: `_git_apply_delta` checks the declared base size.
- **E5**: only a terminated sitsig line is honoured.
- **E6**: `verify-commit` requires a commit object.
- **E7**: checkout validates the branch name.
- **E8 / E9**: ref names read from disk, `config --list` and `remote list` are printed sanitized. This finishes the deferred 2026-08-18 config item.
- **E11**: `sit mv` refuses symlinked parents.
- **E12**: NTFS 8.3 `GIT~1` / `SIT~1` names are rejected.
- **E13**: `@{N}` is capped at nine digits instead of wrapping.
- **E15**: a failed key write removes the partial key instead of locking `key generate` out.

**Partial:**
- **A14**: the ignored returns that could lose data now stop or report. A stash whose file cannot be saved now stops instead of recording it as deleted; the `MERGE_HEAD`, rebase-todo and marker writes are checked; the conflict-path blob read is reported.
- **C10**: plain http got a 30 s read bound; ssh did not.

**Deferred:**
- **B13**: `sit add` ignores directory-only and nested ignore rules.
- **B14**: no `\ No newline at end of file` marker.
- **E10**: bytes ≥ 0x80 (C1 controls, bidi) pass `refname_valid` and `write_sanitized`.
- **E14**: `describe` is first-parent only, nondeterministic on ties, and ignores nested tags.

## External research (P(-1) step 4)

Checked against git's and Git-hosting CVE history up to October 2026:
- **Gitea CVE-2026-95106** (duplicate tree entry names hiding content from review): applies, fixed as **X1**.
- **git CVE-2025-48384** (trailing CR in config values, read/write asymmetry): does not apply. `config_value_valid` rejects CR and LF on write, and sit has no submodules.
- **CVE-2014-9390 / CVE-2019-1353** (`.git` spoofing via case, HFS-ignorable code points and NTFS 8.3): case and HFS were already covered (1.4.8); 8.3 was not, and is fixed as **E12**.
- **CVE-2021-21300 / CVE-2024-32002** (writes beyond a symlinked directory): fixed as **B8 / E1**. sit trees cannot carry symlinks (mode 120000 is rejected), so this needs a symlink already in the worktree or in `.sit/`.
- **CVE-2017-1000117** (ssh argument injection): re-checked after the 1.6.0 ssh changes; clean.

## Verification

- **Unit:** 413 / 413, up from 383. New groups cover the short write, `parse_tree` order and duplicates, and the pure audit guards (merge overlap, binary merge, NTFS 8.3, the `@{N}` cap).
- **Integration:** 244 / 244, up from 207. Section 22 has one scenario per repro-confirmed finding. Run against the 1.6.3 binary, **33 of its assertions fail**, which proves they catch the bugs.
- **Fuzz:** 15 harnesses, no crashes. **Lint and `cyrius audit`:** clean.
- **Under poisoned allocators** (`CYRIUS_POISON=1`, cyrius 6.6.18+): unit 413 / 413, the integration suite against a poison-built `sit`, and fuzz legs A (fill 0xA5) and B (0x5A) all ran with no redzone overwrite, and the A/B outputs are byte-identical, so no overread was detected. Mutation check: 1.4.7's demonstration (`parse_tree`'s name buffer shrunk to 8 bytes) still passes plain fuzzing ("no crashes"), but under poison exits 86 at the first overflow. This is now a CI step, which closes the roadmap's highest-leverage upstream ask.
- **CI smoke steps,** run locally against a workspace copy: diff `-U<N>`, init/add/commit/log, reflog, integration, `.sitignore`, fsck reachability, signed commit, wire protocol, http, https and http push + bearer all pass. The ssh smoke needs sshd and was not run.
- **Builds:**
  - x86_64 (plain and DCE), `--aarch64`, and `--agnos` (plain and DCE), all from a clean `lib/`.
  - The arm64 symlink guard was verified under qemu.
- **Downstream:**
  - **owl** (cyrius 6.6.2) builds and passes its tests against the new `dist/sit-read.cyr`. Its first attempt failed on a stdlib-internal `_io_write_full` this pass had introduced, now replaced by the sit-owned `sit_write_full`.
  - **thoth** (6.6.6) builds on x86_64 and aarch64 and passes 2,330 / 2,331 of its core tests. The one failure is its own pin assertion ("sit-read pinned at 1.6.2"), which flips when thoth re-vendors.
- **Benchmarks** (`tests/sit.bcyr`, best of two runs each, 1.6.3 vs 1.6.4, [`../benchmarks/2026-10-19-v1.6.4.md`](../benchmarks/2026-10-19-v1.6.4.md)): flat. Everything is within ±4% except `tree_flat_path_valid` at +7.2% (609 → 653 ns, consistent across runs).

## Result

All 16 HIGH findings are fixed and each has a regression test that fails on 1.6.3; 17 MEDIUM and 23 LOW are fixed besides. What is left is design work: per-remote credentials, a request arena, a windowed pack reader, a three-way stash pop and unmerged-path tracking. All of it is named on the roadmap.

The 2026-08-18 lesson ("the worst defect was in the code that looked boring") held again, with a sharper form: **every data-loss bug here was a command that did not check something another command already checked.**
- `merge` refused a dirty tree; `cherry-pick` did not.
- `checkout` refused untracked files; `merge` did not.
- `reset` materialized before moving HEAD; `pull` did not.
- `commit` cleared `MERGE_HEAD`; nothing cleared `CHERRY_PICK_HEAD`.

The fix in each case was to move the check to the shared function, so the next command added inherits it.
