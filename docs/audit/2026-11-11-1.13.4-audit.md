# 2026-11-11 — security pass for 1.13.4

**Scope**: the findings [the 1.12.2 audit](2026-10-20-1.12.2-audit.md) left partly fixed or deferred, as the roadmap's 1.13.4 slot carried them, and the release's own security pass over the code that closes them. Severity as [CLAUDE.md](../../CLAUDE.md) defines it.

## Decided

**Links below a real store** (a `.git/` with `refs` and `objects` linked into another repository) are read as git reads them, and not refused. See [ADR 0003](../adr/0003-no-upward-repo-discovery.md)'s 1.13.4 amendment. The exposure is read-only and limited to what the user can read already, `git-new-workdir` makes the shape, and alternates reach as far by design.

## Reviewed

- **Input validation, the connectivity walk.** It parses pushed commits, trees and tags, and none of them is trusted. Commits go through `parse_commit_body_a` (git's header order). A tree is scanned in place, and an entry that runs past the body is a hole, not a skip. Tags peel at most `TAG_PEEL_MAX` links, and only `object <64 hex>\n` is read from one. Trees recurse at most `_TREE_MAX_DEPTH` (256) levels. Every object read counts against the 60 s request budget (`_cn_tick`), and the walk returns -1 (503) past it. Ids reach SQL only through `db_row_read_raw`'s `hex_prefix_valid` gate. A gitlink (160000) is not followed, as git does not follow one.
- **Input validation, the readers.** A line is LF-terminated, and bytes after the last LF are not a line. A line past `RLOG_LINE_MAX` (64 MiB) fails the read, and fsck then counts the log unread and refuses `--prune` rather than lose that line's oids. The per-line oid reader checks the line's own length. Before 1.13.4 the buffer readers checked against the whole buffer, so a short line could be read into the next one.
- **Buffers.** `seg[264]` holds a segment `_serve_repo_name_valid` caps at 255. `w[48]`, `cell` (`SERVE_REPO_CELL` = 72) and the `CN_NODE` / `CN_BASE` records (40) match their layouts. `_serve_fd_path` writes at most 14 + 20 digits + NUL into 40 bytes. `_sit_in_dotdir` reads a byte at a time, so a shorter path stops at its NUL. The readers' buffers grow by doubling, from `_rlog_chunk`, and a moved partial line is copied a byte at a time, since the regions overlap.
- **Syscalls.** Every `openat` / `fstat` / `fstatat` / `lseek` / `read` return is checked, and every failure path closes what it opened: the walk's intermediate descriptors, both descriptors on a failed `.sit` or HEAD check, a kept cell's on drop and on eviction. The descriptor flags come from the stdlib's per-architecture constants (x86_64 and aarch64 disagree on `O_DIRECTORY` and `O_NOFOLLOW`). The code is behind `#ifdef CYRIUS_TARGET_LINUX` / `#ifndef CYRIUS_TARGET_MACOS`. The `--agnos` and aarch64 builds compile.
- **Writes.** The streamed rewrite takes the same path as `sf_write_atomic`: `_sf_parent_symlink`, then an `O_EXCL` lock file, fsync and rename, under the log's flock. A failed write removes the lock file. The `.sit` pin changes where `.sit/…` resolves, not which guards run. `_sf_parent_symlink` skips only the pinned component itself.
- **No command injection, no new external input on the CLI.** The client's new message is a fixed string. The 409 body is matched on a 15-byte prefix and never printed.

## Left open

- **Below `.sit`, within one call** (architecture 010): a guard's `lstat` and its open are two calls. The window is a call wide, where S3's was a request wide.
- **Where nothing can be pinned** (no `/proc`, AGNOS, macOS), `--repos` keeps 1.12.2's per-request path check, says so at start, and still races.
- **macOS is not built here.** The toolchain has no macOS target, so the descriptor code's guards are checked by reading, not by a build. 1.13.3's macOS proof came from thoth's lanes.
- **The connectivity check trusts what the refs reach**, as git's does. A store already holed before 1.13.4 stays holed until `sit fsck` finds it.
