**`lcs-diff` is 9–11% faster** (1000×1000: 34.02 → 31.02 ms). That comes from how 1.7.2 stores the final-newline state (B14). The flag lives in a high bit of each line record's length word. `lines_equal`, the LCS inner loop, now compares the two raw words once, where it used to make two `line_len` calls and compare the results.

The first cut of B14 added a third field to a 24-byte record and compared it separately. It cost the same loop **10–13%** (1000×1000: 34.16 → 38.65 ms; 100×100: 386.03 → 426.59 µs; spreads ≤ 2%). It was measured, rejected and replaced before release.

Everything else is flat:
- `is_ignored` +1.8–2.0% is at the noise floor. Its code did not change; `add` now calls it once per ancestor directory, which this bench does not exercise.
- `copy-objects-100` is unchanged by the new read-miss check.

## Head-to-head vs git — `scripts/benchmark.sh` (100-commit / 100-file fixture)

Two interleaved passes per build; each row is the pass with the lower min.

| operation | git (min / med) | sit 1.7.1 (min / med) | sit 1.7.2 (min / med) | 1.7.2 ÷ git |
|---|---:|---:|---:|---:|
| `init` | 2.85 / 3.05 ms | 1.81 / 1.91 ms | 1.73 / 1.91 ms | 0.61x |
| `add-1KB` | 2.35 / 2.53 ms | 2.49 / 2.73 ms | 2.59 / 2.73 ms | 1.10x |
| `add-64KB` | 3.17 / 3.44 ms | 8.55 / 8.72 ms | 8.52 / 8.79 ms | 2.69x |
| `add-1MB` | 16.27 / 16.80 ms | 100.20 / 100.46 ms | 99.30 / 100.34 ms | 6.10x |
| `commit` | 4.16 / 4.53 ms | 2.59 / 2.77 ms | 2.52 / 2.77 ms | 0.61x |
| `log-100commits` | 4.10 / 4.30 ms | 9.31 / 9.65 ms | 9.39 / 9.72 ms | 2.29x |
| `status-100files` | 3.34 / 3.56 ms | 4.06 / 4.29 ms | 4.03 / 4.29 ms | 1.21x |
| `diff-edit` | 2.53 / 2.90 ms | 11.93 / 12.39 ms | 11.31 / 11.68 ms | 4.47x |
| `clone-100commits` | 14.16 / 14.60 ms | 60.88 / 62.18 ms | 60.80 / 62.04 ms | 4.29x |
| `fetch-1commit` | 11.32 / 11.49 ms | 2.77 / 2.93 ms | 2.82 / 3.00 ms | 0.25x |

`diff-edit` is 5% faster (11.93 → 11.31 ms). It follows the `lcs-diff` win, and a controlled A/B confirms it: one fixture, 200 alternating runs per build, 1.7.1 min 10.11 / median 10.90 ms against 1.7.2 min 9.43 / median 10.18 ms, with byte-identical output.

`log-100commits` is unchanged (9.31 → 9.39 ms) although every message line now goes through the UTF-8-aware `write_sanitized`. The other rows are within noise. `add-1KB`'s +4% min sits on identical medians (2.73 ms).
