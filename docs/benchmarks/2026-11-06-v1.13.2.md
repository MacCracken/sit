# Benchmarks — 2026-11-06 (v1.13.2, cyrius 6.7.18)

The read API and `blame` against 1.13.1. Same toolchain, DCE builds of the CLI, and the read bundle through `read_result_probe.cyr` / `api_heap_probe.cyr`. The previous snapshot is [`2026-10-30-v1.13.0.md`](2026-10-30-v1.13.0.md). No micro CSV: `tests/sit.bcyr` gained nothing, and the host was never quiet.

## One path through a hostile tree

The issue's repro: a 20-deep chain of 255-byte names over N subtrees of 1,000 empty blobs, a 200 KB `.git`. Peak RSS (VmHWM) viewing a clean 12-byte file. The 1.13.1 column is the issue's measure through owl 1.5.3.

| HEAD tree | 1.13.1 | 1.13.2 |
|---|---:|---:|
| N = 100 | 1,731 MB, 7.3 s | 5.2 MB |
| N = 2,000 | out of memory | 5.2 MB |

## What a call keeps, a real tree

100,000 files in 1,000 directories, packed. Bump heap kept per call, and RSS grown over three calls.

| | 1.13.1 | 1.13.2 |
|---|---:|---:|
| `sit_diff_path` | 31,955,208 B, 108 MB | 200 B, 0 |
| `sit_repo_status` | 50,607,832 B, 160 MB | 50,607,968 B, 147 MB |

Status still flattens the tree, as it must without git's index. Roadmap 1.16.2 is the arena that takes this down.

## blame

10,000 files, 41 commits touching the blamed file and one other. Output byte-identical.

| | 1.13.1 | 1.13.2 |
|---|---:|---:|
| `sit blame target.txt` | 4,187 ms | 36 ms |

The same command is 3 ms on a 100,000-file `.git/` repository, where 1.13.1 refused.

## The ignore matcher

`_wildmatch` gained a compare per literal byte for `\\` escapes, on a path the project has measured before. Alternating runs at the same load: `is_ignored-10pat` 8.66 → 8.55 µs, `-50pat` 43.0 → 42.6 µs. `sit status` on 100,000 files: 2,333 → 2,324 ms. A first unpaired run read +12%, with background jobs running. It did not reproduce, and pairing is why [the 1.13.0 snapshot](2026-10-30-v1.13.0.md) alternates too.
