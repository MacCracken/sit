# Benchmarks — 2026-10-19 (v1.7.6)

cyrius **6.7.15** for both builds. The previous snapshot is [`2026-10-19-v1.7.5.md`](2026-10-19-v1.7.5.md).

⚠ **The host was saturated again** (load average 12–24 on 16 cores, other sessions building). As for 1.7.5, the standard `tests/sit.bcyr` and `scripts/benchmark.sh` tables are not published; the changed paths are compared by each child's own CPU time, which excludes time spent preempted. Memory figures are exact counts and peak RSS, unaffected by load. Re-take the standard tables on a quiet host.

## Time — everyday commands, A/B by CPU time

DCE builds, minimum of 15 runs with 1.7.5 and 1.7.6 alternating (`ab176.py`). Wall time is shown where the change adds I/O the CPU column cannot see (fsync), and is noisy at this load.

| operation | 1.7.5 CPU | 1.7.6 CPU | Δ | 1.7.5 wall | 1.7.6 wall |
|---|---:|---:|---:|---:|---:|
| `add` ×100, one file each | 135.1 ms | 162.4 ms | +20.2% | 321 ms | 389 ms |
| `commit` | 2.4 ms | 2.4 ms | +2.7% | 2.8 ms | 3.2 ms |
| `status`, 200 files | 9.6 ms | 10.1 ms | +5.3% | | |
| `log --oneline`, 300 commits | 48.5 ms | 49.1 ms | +1.4% | | |
| `checkout` of 100 changed files, there and back | 123.8 ms | 122.9 ms | -0.7% | | |
| `clone`, 100 commits (file://) | 78.8 ms | 90.3 ms | +14.5% | | |
| `fsck`, 100 commits | 93.8 ms | 88.8 ms | -5.3% | | |

The costs are the fixes:
- **`add`** runs each index write in one patra transaction (L12): about 0.27 ms of CPU and 0.7 ms of wall per file, for a write that is reported when it fails.
- **`clone`** verifies every object it stores (N1): one SHA-256 pass over the received bytes. On 500 compressible 21 KB blobs the clone is 0.63 s of CPU against 0.44 s (minimum of three).
- **`commit`** writes its ref through a lock file, fsync and rename (L5): about 0.4 ms of wall.
- **`status`** stats each path before opening it (R11): +5%.
