# Benchmarks — 2026-10-20 (v1.12.2, the closeout baseline)

cyrius **6.7.15** for every build (DCE). The previous snapshot is [`2026-10-20-v1.11.0.md`](2026-10-20-v1.11.0.md). The previous closeout is [`2026-10-19-v1.7.6.md`](2026-10-19-v1.7.6.md). The CSV beside this file is the new baseline.

The host was quiet for the command table, at a load average of about 3 on 16 cores: the first such window since 1.7.x. Load rose to 3–12 during the micro-benchmarks and to 13–15 during the server runs, and those tables say so.

## Commands — the last closeout to this one

CPU time of each child, minimum of 9 runs. The five builds alternate in order, then in reverse. This re-takes the 1.11.0 table, which was measured at load ~25 and drew no conclusion.

| operation (ms) | 1.7.6 | 1.10.1 | 1.11.0 | 1.12.1 | 1.12.2 |
|---|---:|---:|---:|---:|---:|
| add ×100 (one file each) | 100.8 | 111.0 (+10.2%) | 110.4 (+9.5%) | 111.3 (+10.5%) | 112.2 (+11.3%) |
| commit | 1.5 | 1.5 (−1.4%) | 1.5 (−3.6%) | 1.6 (+4.7%) | 1.5 (+0.6%) |
| status, 200 files | 5.5 | 5.6 (+1.8%) | 5.6 (+1.6%) | 5.7 (+4.0%) | 5.7 (+3.4%) |
| log --oneline, 300 commits | 23.6 | 23.7 (+0.2%) | 23.9 (+1.1%) | 24.2 (+2.4%) | 23.8 (+0.8%) |
| checkout 100 changed files, there and back | 66.4 | 67.2 (+1.2%) | 68.3 (+2.9%) | 68.6 (+3.5%) | 67.8 (+2.2%) |
| clone, 100 commits | 44.0 | 44.5 (+1.1%) | 45.1 (+2.4%) | 45.4 (+3.2%) | 45.0 (+2.1%) |
| fsck, 100 commits | 43.3 | 42.7 (−1.4%) | 42.9 (−0.9%) | 43.3 (+0.1%) | 42.6 (−1.5%) |

- **1.12.1 → 1.12.2: no path got slower.** Everything is within ±2%, except `commit`, which is 6% faster.
- **1.10.1 → 1.11.0 (the re-take):** every path moved between −2.2% (`commit`, whose 1.5 ms is at the table's 0.1 ms precision) and +1.6% (`checkout`). 1.11.0's one new cost per command, a `stat` when the store opens, is not visible. The 1.11.0 snapshot's −23% on `status` was the host, as it said.
- **1.7.6 → 1.12.2:** `add ×100` costs about 0.11 ms more per invocation, all of it arriving by 1.10.1. That fits what 1.9.0 measured for the cmdit dispatch (0.05–0.08 ms per invocation) plus 1.10.0's store-lock open; nothing since has added to it. The other operations are within +3.4% of the last closeout.

## The --repos server (1.12.2's per-request checks)

Server CPU over 4,000 requests, minimum of 6 alternating runs. The repository sits at a two-segment name, packed by gc. Two runs at host load 13–15:

| | 1.12.1 | 1.12.2, run 1 | 1.12.2, run 2 |
|---|---:|---:|---:|
| `GET /refs` | 122.5 / 120.0 µs | 135.0 µs | 120.0 µs |
| `GET /objects/<HEAD>` | 455.0 / 340.0 µs | 407.5 µs | 347.5 µs |

The re-check (up to four `lstat`s here, plus one `stat` of the store) is within the noise. The clock's resolution is 2.5 µs per request.

## Micro-benchmarks (`tests/sit.bcyr`)

Minimum of 3 runs, alternating between the 1.7.6 tree and this one, built with the same toolchain. Nothing regressed. The spread is the noise floor: code unchanged since 1.7.6, such as `sha256` and `zlib-compress`, moved by −1% to −22%. The full table is in the CSV. The six `pack-chain-*` / `delta-tree-*` rows are new since 1.10.0 and have no 1.7.6 counterpart.
