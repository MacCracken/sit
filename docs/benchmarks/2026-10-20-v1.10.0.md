# Benchmarks — 2026-10-20 (v1.10.0)

cyrius **6.7.15** for both builds (DCE). The previous snapshot is [`2026-10-19-v1.7.6.md`](2026-10-19-v1.7.6.md). 1.10.0 adds packs and `sit gc` ([ADR 0016](../adr/0016-packs-for-storage.md)), so the headline numbers compare a repository before and after gc.

The host was busy (load average 2–5 on 16 cores). Each figure is a minimum: 5–7 runs for the fixture table, 7 alternating runs (CPU time) for the A/B, and 3 runs for the micro table.

## Storage — the 1,600-commit fixture

`scripts/benchmark.sh`'s history at `FIXTURE_COMMITS=1600`: one file added per commit, so each root tree is the previous one plus an entry. Built with the 1.9.0 binary; git's side was built the same way with git 2.56.

| | bytes |
|---|---:|
| sit 1.9.0, `objects.patra` | 65,908,736 (62.8 MiB) |
| sit 1.10.0 after `sit gc`: pack + idx + rows | 682,782 + 193,096 + 20,480 = **896,358** (875 KiB) |
| git, `--object-format=sha256`, after `git gc`: pack + idx + rev | 818,501 + 193,096 + 19,276 = 1,030,873 |
| git, SHA-1, after `git gc`: pack + idx + rev | 621,132 + 135,472 + 19,252 = 775,856 |

The index is the same size on both SHA-256 sides because it is the same format: `git index-pack` rebuilds sit's byte for byte.

Delta structure (`git verify-pack -v` on sit's pack): one tree of 1,600 is stored whole, and the deepest chain is 10 (skip-deltas). The whole trees, then the commits (251 KB, not deltified), make up most of the pack. The first cut chained each tree to the next up to depth 50 and kept 33 whole trees: pack 1.41 MB, 62% of it whole trees. git, for comparison, keeps 17 whole trees and chains of at most 12.

## Time — the same fixture, unpacked under 1.9.0 vs packed under 1.10.0

| operation | unpacked, 1.9.0 (ms) | packed, 1.10.0 (ms) |
|---|---:|---:|
| `log --oneline` | 116.2 | 61.8 (−47%) |
| `status` | 31.7 | 31.3 (−1%) |
| `show --stat` of the oldest commit | 4.4 | 4.2 (−5%) |
| `fsck` | 7,106 | 2,018 (−72%) |
| `clone` (file://) | 5,789 | 6,955 (+20%) |

Clone is slower from a packed repository, because a packed object leaves the store expanded and compressed (level 1; level 6 cost +43%). The receiver stores it loose. Packs on the wire are a roadmap item.

`sit gc` on the fixture: 5.3 s the first time (2.8 s of it reading 63 MB of rows out of patra; 0.43 s reading the new pack back to verify it) and 2.6 s on a repeat (git: 0.6 s). Before the delta base cache, the read-back alone took 3.7 s.
