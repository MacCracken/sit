# Benchmarks — 2026-10-19 (v1.7.4)

cyrius **6.7.15** for both builds. 1.7.3 and 1.7.4 were measured interleaved on a quiet host. The previous snapshot is [`2026-10-19-v1.7.3.md`](2026-10-19-v1.7.3.md). Deltas under ~3% are noise.

## `sit serve` — memory per request and per connection

Bytes kept on the global (no-free) heap per request, measured by calling `serve_handle_request` directly against a three-commit repo:

| request | 1.7.3 | 1.7.4 |
|---|---:|---:|
| `GET /sit/v1/refs` (two refs; more per ref) | 3,528 | 0 |
| `GET /sit/v1/capabilities` | 704 | 0 |
| `GET /sit/v1/objects/<id>` | 472 | 0 |
| the same, not found | 272 | 0 |
| `POST /sit/v1/want` | 368 | 0 |
| an unknown path | 192 | 0 |
| `POST /sit/v1/objects/<id>` (push) | 384 | 32 |
| `POST /sit/v1/refs/<name>` (push, no-op) | 1,056 | 152 |

The push residuals are sankoch's per-call 32 B in `zlib_decompress`, and the shared ref-write helpers.

Server RSS (VmRSS, a fresh connection per request, after 50 warm-up requests):

| load | 1.7.3 | 1.7.4 |
|---|---|---|
| 5,000 requests to each of six read endpoints, plain HTTP | 4.9 → 38.1 MB | 6.9 → 7.2 MB |
| 1,000 TLS connections, one handshake each | 7.9 → 83.6 MB (~77.6 KB each) | 7.2 → 7.2 MB |
| 5,000 `GET /refs` on one TLS keep-alive connection | — | flat |

## git read mode — reading every blob in-process

A git repo of one file edited in 320 commits, repacked at `--depth=50` (both versions can read it), through `read_object`, three runs each:

| | 1.7.3 | 1.7.4 |
|---|---:|---:|
| time for all 320 blobs | 455–462 ms | 459–463 ms |
| bump heap kept | 220 MB | 568 KB |

At `--depth=300` (deepest chain 251) 1.7.3 cannot read the 237 blobs deeper than 64. 1.7.4 reads all 320 in 1.93 s, keeping 1.5 MB.

A first version took a fresh freelist block per delta step and was 28% slower, because every block over 4 KiB is its own mapping. The shipped resolver reuses two result buffers and one delta buffer per read.
