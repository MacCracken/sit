# Benchmarks — 2026-10-19 (v1.7.1)

cyrius **6.7.15** (patra **1.16.5**, sigil 3.13.12, sankoch 2.8.7, sandhi 1.13.1). 1.7.0 (cyrius 6.7.9) and 1.7.1 were measured back to back, interleaved, on the same host. The previous snapshot is [`2026-10-19-v1.7.0.md`](2026-10-19-v1.7.0.md).

⚠ An unrelated compile job loaded the host (load average ~9 on 16 cores) through the first two micro runs, which read 15–45% slow on **both** builds. The tables below use the two later runs, taken at load ~2–3, which agree within 4%. All four runs are kept in the raw notes below. Deltas under ~3% are noise.

**One move tracks the toolchain bump: `patra-open-close` +7.6% (27.14 → 29.20 µs).** It was the same in both quiet runs, and +16% in the loaded ones. patra 1.16.2 verifies the database header and checks every sync status on the open / close path, and `patra_init` reserves 48 KB more; the move fits that, but it was not bisected. **Everything else is flat**, including `copy-objects-100` (172.03 vs 172.04 µs): 1.7.1's checked insert and commit statuses cost nothing measurable. Two interleaved passes per build on the quiet host; each row is the pass with the lower min.

Unchanged within noise. `clone-100commits` read 68.29 vs 63.05 ms in the first quiet pass and 71.31 vs 71.37 ms in the second, so its apparent −8% is pass-to-pass variance, not a win. The extra patra open cost does not surface at command level. Every ratio is within 0.2x of the 1.7.0 snapshot's.
