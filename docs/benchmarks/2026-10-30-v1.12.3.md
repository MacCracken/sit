# Benchmarks — 2026-10-30 (v1.12.3, cyrius 6.7.18)

A toolchain A/B. Both columns are DCE builds of the same source: 1.12.2 at cyrius **6.7.15**, and 1.12.3 at **6.7.18** with cmdit 1.5.0. The previous snapshot is [`2026-10-20-v1.12.2.md`](2026-10-20-v1.12.2.md), the 1.12.x closeout baseline. The CSV beside this file is the new baseline.

The host was at a load average of 1.6–6 on 16 cores throughout.

## Commands

CPU time of each child, minimum of 9 runs. The two builds alternate in order, then in reverse. All fixtures were written by the 1.12.3 build; 1.12.2 reads them unchanged.

| operation (ms) | 1.12.2 | 1.12.3 |
|---|---:|---:|
| add ×100 (one file each) | 104.2 | 102.5 (−1.7%) |
| commit | 1.2 | 1.2 (−0.8%) |
| status, 200 files | 5.2 | 5.1 (−1.6%) |
| log --oneline, 300 commits | 22.9 | 22.9 (0.0%) |
| checkout 100 changed files, there and back | 38.2 | 37.9 (−0.9%) |
| clone, 100 commits | 36.4 | 36.7 (+1.0%) |
| fsck, 100 commits | 31.0 | 31.7 (+2.1%) |

- **Nothing moved beyond ±2.1%.**
- **Compare columns within this table only.** The fixtures differ from the 1.12.2 snapshot's: different file contents, and a `file://` clone. That is why `checkout` and `fsck` read lower here than in that table.

## What the refresh bought

| | 1.12.2 | 1.12.3 | source |
|---|---:|---:|---|
| git-mode read, bump heap kept per object (loose and undeltified packed) | 32 B | 0 B | sankoch 2.8.9 |
| ref push over 300 commits, bump heap kept (refused or accepted) | 9,568 B | 0 B | sankoch 2.8.9 |
| sandhi's framing calls on a request with a body, bump heap kept over 100 requests | 1,600 B | 0 B | sandhi 1.13.2 |
| `sit serve`, RSS growth over 200,000 POSTs with a 64-byte body | 2,048 KB | 0 KB | sandhi 1.13.2 |

The first three come from the integration probes: `read_heap_probe.cyr` for section 29, and `serve_push_probe.cyr` for section 30, whose `BODYREQ` line (30c) is new in 1.12.3. Since 1.12.3 all three are bounded at 0. The fourth is a plain `sit serve --listen` under a fresh connection per request, at the same 2 MiB page granularity in both columns.

## Micro-benchmarks (`tests/sit.bcyr`)

Minimum of 2 runs, alternating between the two trees. The full table is in the CSV.

- **zlib:** compress and decompress are 0.6–3.6% faster.
- **Everything above 1 µs is within ±4%**, except `pack-chain-50-warm` (+6.6%).
- **The sub-microsecond validator rows** moved by −7.8% … +8.6%. They sit near the 1.3 µs timer floor, which the harness subtracts, so that spread is noise.
