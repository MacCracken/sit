# Benchmarks — 2026-11-11 (v1.13.4, cyrius 6.7.18)

What the four 1.12.2-audit fixes cost and change, against 1.13.3 built from its tag on the same host, toolchain and day. The previous snapshot is [`2026-11-06-v1.13.2.md`](2026-11-06-v1.13.2.md). No micro CSV: `tests/sit.bcyr` reaches none of the changed paths, and its run matched 1.13.2's within noise.

## `--repos` through descriptors (S3)

`tests/integration/swap_race.py`, 300 rounds of `GET /team/sit/v1/refs` plus a ref push. Meanwhile a child process exchanges `<dir>/team` with a link to an outside repository (`renameat2(RENAME_EXCHANGE)`) as fast as it can.

| | 1.13.3 | 1.13.4 |
|---|---:|---:|
| refs answers that showed the outside repository's tip | 119 | 0 |
| branches written into the outside repository | 35 | 0 |

The cost per request: 3,000 `GET /refs` on a three-segment name (`a/b/team`), one connection each, three alternating runs.

| | 1.13.3 | 1.13.4 |
|---|---:|---:|
| µs per request | 172.0, 166.2, 170.6 (169.6) | 179.1, 171.5, 178.4 (176.3) |

About 7 µs per request. For this name the walk is four `openat`s, an `fstatat`, two `fstat`s and four `close`s, against 1.12.2's five `lstat`s and a `stat`.

## Connectivity before a served ref moves (X2c)

A 300-commit history of 1,506 objects in three directories, pushed with `sit push` over http to a fresh `sit serve`. Whole client commands, which send every reachable object each time (the server answers 200 for one it has).

| push | 1.13.3 | 1.13.4 |
|---|---:|---:|
| first push (every object checked) | 0.42 s | 0.54 s |
| one more commit | 0.375 s | 0.371 s |
| a branch forked 290 commits back, plus one commit | 0.372 s | 0.376 s |

A push onto the old tip, or onto history the refs reach, checks the new commits and the paths they changed. The forked branch stops where the refs' history meets it, because the walk takes commits by committer date.

## Reflogs past 64 MiB (L5)

A 70 MiB `.sit/logs/HEAD` (424,924 entries).

| | 1.13.3 | 1.13.4 |
|---|---|---:|
| `sit reflog -n 2` | prints nothing | ~1 ms |
| `sit show HEAD@{1}` | "no object matches" | ~1 ms |
| `sit show HEAD@{2001-09-10}` (80,000 entries back) | "no object matches" | resolves |
| `sit reflog` (every entry) | prints nothing | 0.45 s |
| `sit reflog delete HEAD@{3}` | nothing | 0.71 s |
| `sit reflog expire --expire=2010-01-01 HEAD` | "expired 0" | 0.57 s, 424,922 expired |
| `sit fsck --prune-now` | refused | 0.60 s |

`@{n}` and `reflog -n` read the log's tail only, backward, so they cost the same on any size.
